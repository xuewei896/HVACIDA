# HVACIDA 开发流程(团队 + AI 协作版)

> 本文档是项目开发的操作手册:总流程 → 单模块迭代 → 模块状态看板 → 每轮验证清单 → 领域口径记录 → Git 规范。
> 配套阅读:`README.md`(工程结构/编译)、`HVACIDA_需求分析文档.md`(需求)、`大系统负荷计算公式.docx` 及 `-示例.xls`(公式权威输入)。

## 1. 项目级总流程

```
① 需求/公式基线 → ② 模块设计 → ③ 编码(分层) → ④ 编译门禁
→ ⑤ 数值回归/结构自检 → ⑥ Revit 实机验证 → ⑦ 数据与报表 → ⑧ 集成模块
→ ⑨ 部署分发与验收
```

| 阶段 | 做什么 | 产出/出口标准 |
|---|---|---|
| ① 需求/公式基线 | 把需求文档条目与公式文档(docx/xls)整理成"输入→期望输出";**交付 docx 先过 `tools/docx2md` 抽一份 Markdown 正文副本**(见 §5.4) | 每模块一份算例(无算例则列明"待领域确认"项);docx 与副本 SHA256 一致 |
| ② 模块设计 | Models / Service 接口 / 常量(`Utils/HvacConstants.cs`) | 命名空间与需求章节一一对应 |
| ③ 编码 | 固定顺序 **Core(可单测)→ UI(WPF/MVVM)→ Revit(外壳/API)** | 各层职责:Core 无 Revit 依赖;UI 不引用 Revit API;Revit 引用两者 |
| ④ 编译门禁 | VS MSBuild 全解决方案 Debug/Release | **0 错误 0 警告**,三个 DLL 产出 |
| ⑤ 数值回归/结构自检 | `tools/HVACIDA.Smoke`(数值 + 目录/仓库/知识库)+ `window-smoke.ps1`(窗口装载)+ `ribbon-smoke.ps1`(Ribbon 结构) | 与算例逐格一致(现 30 项 PASS);三项自检全绿(见 §5.3) |
| ⑥ Revit 实机验证 | 用户本机 `deploy/install.ps1` → 重启 Revit 2020 冒烟 | 见 §6 实机清单 |
| ⑦ 数据与报表 | SQLite 化、计算书 txt→Excel/PDF | 接口不变,实现可替换 |
| ⑧ 集成模块 | 水力(风/水)、材料表、出图、AI 问答 | 按依赖顺序逐个替换占位 |
| ⑨ 部署与验收 | `.addin` 分发(或打包);对照需求文档第 6 章验收 | 验收逐条签字 |

### 5.2 WPF 绑定一致性(防"静默留空")
**已自动化**:`window-smoke.ps1` 开头会对 **12 个窗口 XAML** 做反射校验 —— 把每个 `{Binding 路径}` 逐段
在「该窗的 ViewModel + 其集合属性/嵌套对象的元素类型」上解析,解析不到即 FAIL。为什么要下钻元素类型:
DataGrid 列模板里的绑定指向的是**行对象**(如 `SectionText`、`Zeta`),不是 VM;而嵌套对象要再下一层
(如 `Coefficients.LocalLossItems` 的元素类型,得从 `HydraulicCoefficients` 找)。自引用绑定
(`RelativeSource={RelativeSource Self}`)与显式 `Source=` 会被跳过。
> 为什么必须做:WPF 绑定失败是**静默**的 —— 标签在、数字空,不抛异常、不进日志。当前覆盖约 450 条绑定路径。

需要单独查某个模型类型时,仍可用这条手工片段:
```powershell
$asm=[System.Reflection.Assembly]::LoadFrom("D:\DSH\src\HVACIDA.Core\bin\Debug\net48\HVACIDA.Core.dll")
$props=$asm.GetType("HVACIDA.Core.Models.LargeSystemInput").GetProperties('Public,Instance').Name
[regex]::Matches((Get-Content "src\HVACIDA.UI\Views\LargeSystemWindow.xaml" -Raw),'Binding Input\.([A-Za-z0-9_]+)').Groups[1].Value | Sort-Object -Unique | Where-Object { $_ -notin $props }
```

```powershell
#    另含:大系统窗/计算结果窗气象联动同源断言、公共区窗自动识别与手动拾取回填断言、

#    (用临时目录当仓库,不碰 %AppData%\HVACIDA 真实数据)
powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\tools\HVACIDA.Smoke\window-smoke.ps1 `
  -UiDir .\src\HVACIDA.UI\bin\Release\net48

# 3) Ribbon 结构自检:22 个命令注册 + [Transaction] 标注 + 22×2 内嵌图标(齐全/尺寸/可解码/覆盖率)
#    注意:该脚本自身是"父/子两段"(见下方说明),退出码由父进程给出,正常约 5 秒
powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\tools\HVACIDA.Smoke\ribbon-smoke.ps1 `
  -BinDir .\src\HVACIDA.Revit\bin\Release\net48
```
新公式/新算例一律先在 Smoke 加断言;新增/改窗口一律先过 `window-smoke.ps1`;改 Ribbon 结构(含**加/改图标**)一律先过 `ribbon-smoke.ps1`。
**结论必须来自脚本退出码**,不许只靠"肉眼看数字/看界面"。

> **ribbon-smoke 为什么要拆父子两段**:`RevitAPIUI.dll` 是混合模式(C++/CLI)程序集,实测在 Windows PowerShell 5.1 下
> **只要加载它,进程输出完结论后就无法退出**(`exit`、`[Environment]::Exit()` 都无效 —— CLR 关闭挂起;经二分确认与仓库代码无关:
> 只加载 `RevitAPI`+`RevitAPIUI` 即可复现,而 WPF 图像解码本身不复现)。所以脚本把"加载 RevitAPI 的脏活"放进子进程,
> 子进程把结论写成 `GATE-RESULT: PASS|FAIL n` 后强制结束自身,父进程只读结论并给出干净的退出码。
> 直接跑脚本 = 走父进程,行为与退出码都正常;不要把加载 RevitAPI 的代码挪到父进程。

> **改图标**:图标是**生成物**,不要手绘 PNG。改 `tools/HVACIDA.IconGen/Program.cs` 里的几何定义 →
> `HVACIDA.IconGen.exe --out src\HVACIDA.Revit\Resources\Icons`(必要时加 `--preview` 打印 ASCII 自检形状)→
> 重新编译 `HVACIDA.Revit`(PNG 以 `EmbeddedResource` 内嵌进 DLL)→ 跑 `ribbon-smoke.ps1` 校验。

### 5.4 同步门禁(交付 docx ↔ Markdown 副本;**气象库源文件 ↔ 内嵌 CSV**)

需求/公式类交付件是 **.docx(二进制)** —— Git 只能整体覆盖、无法合并,评审也看不清改了哪几行。
所以:docx 有改动,**必须重跑提取器**,让 `docs/` 下的正文副本跟上。

```powershell
# 1) 改了 docx 之后:重新生成正文副本(装了 python-docx 即可: pip install python-docx)
python tools\docx2md\docx_to_markdown.py "通风空调智能设计助手.docx" `
  "docs\需求源文档-通风空调智能设计助手.md" --auto-headings --toc

# 2) 门禁:校验副本头部记录的 SHA256 与当前 docx 是否一致(退出码 0 = 最新)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\docx2md\check-docx-sync.ps1

# 3) 偷懒法:过期就按副本头部记录的命令自动重生成,再校验
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\docx2md\check-docx-sync.ps1 -Regenerate
```

- **气象库同理**:`各省市室外空气参数.md` 是源、`weather-db.csv` 是生成物,改数据只改源文件再重跑生成器。

```powershell

python tools\weatherdb\build_weather_db.py

# 2) 门禁:源文件 SHA256 ↔ CSV 头部记录、台站数、重跑解析校验(退出码 0 = 一致)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\weatherdb\check-weather-db-sync.ps1

# 3) 偷懒法:过期就自动重生成再校验
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\weatherdb\check-weather-db-sync.ps1 -Regenerate
```

  **提示**(标准未记录的湿球温度、装饰列异常)需逐条确认后才能放过;

## 8. Git 协作规范

- 提交粒度:**一个模块/一个公式核对 = 一次提交**,message 用 Conventional Commits(`feat|fix|docs|test|refactor` + 作用域 + 中文说明)。
- 版本管理:本地提交可随时做;**push 由你在本机终端执行**(沙箱无认证):
```powershell
cd D:\DSH
git add -A; git commit -m "类型(作用域): 说明"
git push
```
- 涉及公式/数值的文件(尤其是 `HvacConstants.cs`、计算器、算例)改动必须附 §7 记录或算例断言。
